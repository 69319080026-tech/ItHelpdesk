# ระบบรับแจ้งปัญหา IT (IT Helpdesk)

ระบบสำหรับแจ้งปัญหาด้าน IT, มอบหมายผู้รับงาน, ติดตามความคืบหน้า
และบันทึกประวัติการเปลี่ยนสถานะ (ผู้เปลี่ยน + เวลา) ใช้ได้ทั้งคอมพิวเตอร์และโทรศัพท์ (ติดตั้งเป็นแอปบนหน้าจอโฮมได้)

## เทคโนโลยี
| ส่วน | เทคโนโลยี |
|---|---|
| Front end | HTML/CSS/JavaScript แบบ Responsive + PWA (manifest, service worker) |
| Back end | C# ASP.NET Core 8 Minimal API |
| Database | SQLite ผ่าน Entity Framework Core (`database.sql` คือโครงสร้างตาราง) |
| Test | xUnit |

## วิธีรัน (สำหรับผู้ตรวจ)
1. ติดตั้ง **.NET 8 SDK** (ถ้ายังไม่มี): `winget install Microsoft.DotNet.SDK.8` หรือดาวน์โหลดจาก dotnet.microsoft.com
2. แตกไฟล์ zip แล้วเปิด Terminal ที่โฟลเดอร์หลัก (โฟลเดอร์ที่มี `ItHelpdesk.sln`)
3. รันเว็บ:
   ```
   dotnet run --project ItHelpdesk
   ```
   รอจนขึ้น `Application started` แล้วเปิด **http://localhost:5000**
   - API docs (ทดสอบ API ตรง): http://localhost:5000/swagger
   - ฐานข้อมูล `ItHelpdesk/helpdesk.db` ถูกสร้างอัตโนมัติพร้อมข้อมูลตั้งต้นตอนรันครั้งแรก
4. รันเทสต์อัตโนมัติ (เปิด Terminal อีกหน้าต่าง):
   ```
   dotnet test ItHelpdesk.sln
   ```
   ผลที่คาดหวัง: Passed 15/15

เปิดด้วย Visual Studio 2022: ดับเบิลคลิก `ItHelpdesk.sln` แล้วกด F5

### บัญชีทดสอบ (ระบบสร้างให้อัตโนมัติ ไม่ต้องสร้างเอง)
หน้าเข้าสู่ระบบมีปุ่มบัญชีทดสอบ กดแล้วเข้าได้ทันที

| ชื่อผู้ใช้ | รหัสผ่าน | ชื่อ | บทบาท | เห็น / ทำอะไรได้ |
|---|---|---|---|---|
| `admin` | `admin1234` | สุดา | **Admin** | เห็นใบแจ้งทั้งหมด, มอบหมายงาน, จัดการประเภทปัญหา, เปลี่ยนสถานะได้ทุกขั้น |
| `somchai` | `1234` | สมชาย | พนักงาน | แจ้งปัญหา, เห็นเฉพาะใบของตัวเอง, ยกเลิก/ปิดงาน/เปิดงานซ้ำ |
| `somying` | `1234` | สมหญิง | พนักงาน | เหมือนสมชาย (ใช้ทดสอบว่าพนักงานไม่เห็นใบของกันและกัน) |
| `wichai` | `1234` | วิชัย | ช่าง IT | เห็นเฉพาะงานที่ได้รับมอบหมาย, ดำเนินการ, แก้ไขเสร็จ |
| `prasit` | `1234` | ประสิทธิ์ | ช่าง IT | เหมือนวิชัย |

ความปลอดภัย: รหัสผ่านเก็บแบบ PBKDF2 + salt, ล็อกอินด้วย HttpOnly cookie,
ทุก API ต้องล็อกอิน และระบบอ่านตัวตนจาก cookie เท่านั้น (ปลอม userId ไม่ได้)
ถ้าลืมรหัส: หยุดเว็บ ลบ `ItHelpdesk/helpdesk.db*` แล้วรันใหม่ บัญชีทดสอบจะถูกสร้างกลับมา

### เปิดบนโทรศัพท์
- Wi-Fi วงเดียวกัน: เปิด `http://<IP เครื่อง>:5000` (อาจต้องอนุญาตพอร์ต 5000 ใน Windows Firewall)
- หรือใช้ Cloudflare Tunnel เพื่อได้ลิงก์ https: `cloudflared tunnel --url http://localhost:5000`
- เปิดแล้วกดเมนูเบราว์เซอร์ → "เพิ่มลงในหน้าจอหลัก" เพื่อติดตั้งเป็นแอป (PWA)

## ข้อมูลหลัก
- **Categories** ประเภทปัญหา
- **Tickets** ใบแจ้งปัญหา (หัวข้อ, รายละเอียด, ประเภท, ความสำคัญ, ผู้แจ้ง, ผู้รับ, สถานะ)
- **StatusHistories** ประวัติสถานะ (สถานะเดิม → ใหม่, ผู้เปลี่ยน, เวลา, หมายเหตุ)
- **Users** ผู้ใช้ (พนักงาน / ช่าง IT / Admin)

## เส้นทางสถานะที่อนุญาต
```
Open ──► Assigned ──► InProgress ──► Resolved ──► Closed
  │          │             │             │
  └──────────┴─────────────┴──► Cancelled └──► InProgress (เปิดซ้ำ)
```
- เปลี่ยนนอกเส้นทาง → ระบบปฏิเสธ (HTTP 400) และไม่บันทึกประวัติ
- เปลี่ยนเป็น Assigned ต้องมีผู้รับงานก่อน
- ทุกการเปลี่ยนบันทึก ผู้เปลี่ยน + เวลา ลง StatusHistories

## API
| Method | URL | ใช้ทำ |
|---|---|---|
| GET | /categories | ดูประเภทปัญหา |
| POST | /categories | เพิ่มประเภท |
| GET | /users | ดูผู้ใช้ |
| GET | /tickets?status=&categoryId= | รายการใบแจ้ง |
| GET | /tickets/{id} | รายละเอียด + ประวัติ + สถานะที่ไปต่อได้ |
| POST | /tickets | สร้างใบแจ้ง |
| PATCH | /tickets/{id}/assign | มอบหมายผู้รับ |
| PATCH | /tickets/{id}/status | เปลี่ยนสถานะ |

## กรณีทดสอบ (ItHelpdesk.Tests/TicketTests.cs)
1. สร้างใบแจ้ง → สถานะ Open, มีประวัติ 1 แถว
2. เปลี่ยนเป็น Assigned โดยไม่มีผู้รับ → ถูกปฏิเสธ
3. เดินครบเส้นทางจนถึง Closed → สำเร็จ, มีประวัติ 5 แถว, ผู้เปลี่ยนถูกต้องทุกแถว
4. ข้ามขั้น Open → Resolved → ถูกปฏิเสธ, ไม่เพิ่มประวัติ
5. Closed → สถานะอื่น → ถูกปฏิเสธ
6. ประวัติทุกแถวมีผู้เปลี่ยนและเวลา
7. Resolved → InProgress (เปิดซ้ำ) → สำเร็จ
8. มอบหมายงานให้พนักงานทั่วไป → ถูกปฏิเสธ
9. มอบหมายงานได้เฉพาะ Admin
10. พนักงานกด "แก้ไขเสร็จ" ไม่ได้ (ต้องเป็นช่างที่ได้รับมอบหมาย)
11. ช่างปิดงานแทนผู้แจ้งไม่ได้
12. การมองเห็นตามบทบาท: พนักงานเห็นแค่ใบของตัวเอง, ช่างเห็นแค่งานที่ได้รับ, Admin เห็นทั้งหมด
13. รหัสผ่านถูก hash และตรวจสอบได้ถูกต้อง

## Deploy (ให้ผู้ตรวจเปิดผ่านลิงก์)

### วิธีที่ 1: Azure App Service จาก Visual Studio (แนะนำ)
1. คลิกขวาโปรเจกต์ ItHelpdesk → **Publish** → Azure → Azure App Service (Windows)
2. สร้าง App Service ใหม่ เลือก Plan ราคา **Free (F1)**
3. กด Publish → ได้ลิงก์ `https://<ชื่อแอป>.azurewebsites.net`
ฐานข้อมูลเก็บที่ `%HOME%\data\helpdesk.db` บนเซิร์ฟเวอร์ ไม่หายเมื่อ deploy ใหม่

### วิธีที่ 2: Render (ใช้ Dockerfile)
1. อัปโค้ดขึ้น GitHub
2. render.com → New → Web Service → เลือก repo → Runtime: Docker → Free
3. ได้ลิงก์ `https://<ชื่อ>.onrender.com`
หมายเหตุ: แพ็กเกจฟรีข้อมูลจะรีเซ็ตเมื่อเซิร์ฟเวอร์ถูกปิด/เปิดใหม่ และครั้งแรกอาจโหลดช้า ~1 นาที

ลิงก์ทั้งสองเป็น https → บนโทรศัพท์ติดตั้งเป็นแอปเต็มรูปแบบได้
